# مراجعة الكود الآمنة

## المحاور
1. **المدخلات:** تحقق من النوع والطول والنطاق، وترميز المخرجات حسب السياق.
2. **الاستعلامات:** استعلامات مُعاملة (parameterized) فقط؛ لا تجميع نصوص SQL.
3. **المصادقة:** تجزئة كلمات المرور بـ Argon2id/bcrypt، MFA، وإدارة جلسات آمنة.
4. **التفويض:** تحقق على الخادم لكل طلب؛ لا تعتمد على إخفاء الواجهة.
5. **الأسرار:** لا مفاتيح في الكود أو السجلات؛ متغيرات بيئة أو خزنة أسرار.
6. **الملفات:** تحقق من الامتداد والمحتوى، خزّن خارج جذر الويب، وامنع Path Traversal.
7. **الاعتماديات:** افحصها بـ OSV/Trivy، وثبّت الإصدارات، وراجع التراخيص.
8. **السجلات:** لا تسجّل كلمات مرور أو رموزاً أو بيانات شخصية.
9. **الحدود:** معدل الطلبات، أحجام الرفع، والمهلات.
10. **الأخطاء:** رسائل عامة للمستخدم، تفاصيل آمنة للسجل.

## منهج الإبلاغ
- الخطورة (P0/P1/P2) + الموقع الدقيق + سيناريو الاستغلال + الإصلاح.
- لا تُدرج بيانات حساسة في التقرير.
- اربط كل ملاحظة بدليل من الكود أو اختبار.

## قواعد
- لا تعدّل كوداً خارج نطاق مصرح به.
- لا تشغّل اختبارات اختراق على أنظمة لا تملكها.
- اقترح اختبار انحدار لكل إصلاح.
