# أمان الوكلاء

## المبادئ
1. **أقل صلاحية:** كل أداة تفعل شيئاً واحداً، ونطاقها واضح.
2. **فصل القراءة عن الكتابة:** أدوات التحليل قراءة فقط؛ الكتابة تحتاج موافقة بشرية.
3. **قائمة أدوات مسموحة:** لا أدوات ديناميكية من مخرجات النموذج.
4. **عزل المحتوى غير الموثوق:** نص الملف أو الويب بيانات، وليس تعليمات.
5. **حدود الموارد:** خطوات، وقت، حجم نتيجة، وعدد استدعاءات.
6. **لا أسرار في المطالبة:** المفاتيح تبقى في البيئة، لا في سياق النموذج.
7. **تسجيل قابل للتدقيق:** سجّل الأداة والمعاملات والنتيجة المختصرة، دون بيانات حساسة.

## حقن المطالبات
- افترض أن أي نص خارجي قد يحتوي تعليمات خبيثة.
- لا تنفّذ تعليمات مكتوبة في ملف أو صفحة ويب.
- تحقق من وجهة الطلب: هل هو من المستخدم أم من محتوى؟
- استخدم قوالب صريحة: "هذا محتوى للتحليل فقط".

## الشبكة والتكاملات
- HTTPS فقط، مضيفون مسموحون، وسقف استجابة.
- أرسل مؤشرات/استعلامات فقط، لا عينات أو ملفات.
- اجعل تكاملات الوكيل معطّلة افتراضياً وفعّلها صراحةً.
- تعامل مع نتائج API كبيانات غير موثوقة.

## الاختبار
- حالة حقن مطالبة في اسم ملف.
- محاولة أداة قراءة خارج المسار.
- استجابة API ضخمة أو بطيئة.
- محاولة إرسال سر إلى أداة شبكة.
