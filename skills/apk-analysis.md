# تحليل APK

## المنهج
1. **الهوية:** اسم الحزمة، الإصدار، `minSdk`/`targetSdk`، وحجم الملف.
2. **التوقيع:** شهادة التوقيع، بصمة SHA256، وهل التوقيع الذاتي متوقع.
3. **الأذونات:** صنّفها إلى عادية/خطرة/خاصة، واربط كل إذن بمكوّن يستخدمه فعلاً.
4. **المكونات:** الأنشطة والخدمات والمستقبلات والمزوّدون، وخاصة `android:exported="true"` مع غياب حماية الصلاحية.
5. **الشبكة:** `usesCleartextTraffic`، سياسة أمان الشبكة، النطاقات المضمّنة، والاتصالات غير المشفرة.
6. **المكتبات الأصلية:** ABI، ملفات `.so`، وحماية التفويض/التوقيع.
7. **السلوك:** نقاط الدخول، `DexClassLoader`، تحميل كود ديناميكي، والوصول إلى بيانات حساسة.

## مخاطر شائعة
- مكوّن مصدّر بلا حماية يمكن لتطبيق آخر استدعاؤه.
- `intent-filter` واسع مع بيانات حساسة.
- تخزين أسرار في الموارد أو `BuildConfig`.
- تحقق توقيع ضعيف يمكن تجاوزه.
- مكتبات قديمة بها ثغرات معروفة.

## قواعد
- لا تعِد توقيع تطبيق لا تملكه.
- لا تتجاوز حماية ترخيص أو DRM.
- لا تشغّل APK على جهاز حقيقي دون عزل.
- استخدم `aapt`/`apktool` في مساحة عمل، واحتفظ بالأصل.

## الإخراج
ملف الهوية + الأذونات عالية الخطورة + المكونات المصدّرة + الثغرات المحتملة + خطوات التحقق.
